# 4. 一天一個資料夾的儲存佈局

## Status

Accepted（2026-09-08）

## Context

原本每次錄音在 `lectures/` 底下各開一個資料夾，名稱是 `YYYYMMDD_HHMMSS`。

2026-09-08 那天暴露了問題。一堂 09:03–11:00 的課因為連線不穩被切成四段，`lectures/` 底下就多了四個並排的資料夾，彼此看不出關係：

```text
lectures/
├── 20260908_090321/
├── 20260908_101248/
├── 20260908_101551/
└── 20260908_102416/
```

從檔名看不出這四段是同一堂課，也看不出哪幾天有課。連續上幾週之後，這個目錄會變成幾十個平鋪的資料夾。

另一個需求是整理過的當日筆記。把四段合併成一份可複習的 HTML 之後，那份檔案沒有地方放。擺在 `lectures/` 第一層會跟錄音資料夾混在一起。

## Decision

改成兩層：日期資料夾在外，每次錄音的時間資料夾在內。

```text
lectures/20260908/090321/lecture.wav
lectures/20260908/20260908_上午.HTML
```

`session_id` 維持 `YYYYMMDD_HHMMSS` 不變，只是不再直接當成目錄名。新的 `session_dir_for()` 負責把它拆成兩段路徑，`session_paths()` 呼叫它，其餘所有讀寫都經過 `session_paths()`。

整理過的當日筆記放在日期資料夾的第一層，跟各段錄音並列。

## Consequences

`session_id` 同時是磁碟路徑和 URL 識別碼。這次只改前者，所以 `/download/{session_id}/{filename}` 和 `/finalize/{session_id}` 的網址形式沒變，前端、`session.json` 的欄位語意、既有的路徑驗證正則全部不用動。改動因此收斂成一個新函式。

`/sessions/incomplete` 是全專案唯一直接掃目錄、不經過 `session_paths()` 的地方，它的 glob 從 `*/session.json` 改成 `*/*/session.json`，session_id 的 fallback 也要從一層目錄名改成兩層拼接。這種「唯一的例外」在改佈局時最容易漏掉。

負面與代價：

- **既有資料要手動搬移。** 程式不會自動遷移舊佈局，舊資料夾在新版本下讀不到，`/download` 會回 404。這次是手動 `mv` 處理的。
- 路徑多一層，`cd` 進去多打一次。
- 一天只錄一次課的時候，外層資料夾只包一個子資料夾，看起來有點多餘。
- 日期資料夾的第一層混放整理後的筆記與錄音子資料夾，兩種東西的層級相同但性質不同。替代方案是再開一層 `notes/`，但那會讓最常開的檔案多藏一層。
