# 5. 使用者更正以指示的形式注入後續生成

## Status

Accepted

## Context

摘要管線原本是單向的：逐字稿 → 逐段筆記 → 章節摘要 → 最終整併。使用者在課堂上看得到
筆記寫錯了（ASR 把專有名詞認錯、模型誤解了老師的說法），卻沒有任何地方可以更正。

更糟的是錯誤會傳染。`rollup_prompt` 讀的是逐段筆記，`final_prompt` 讀的是章節摘要，所以
一段寫錯的筆記會被壓縮、再被整併，一路帶進最終筆記，而且沿途看起來愈來愈像定論。

要讓使用者能修正，有兩種做法：

1. **重跑寫錯的那一段**：給每個 note block 一個 id，使用者指定要重寫哪一段，重新呼叫一次
   Anthropic。畫面上立刻修好。
2. **把更正當成指示注入下游**：更正累積成一份清單，跟著素材一起往下游傳，在每一次生成時
   要求模型「與更正衝突時以更正為準」。

## Decision

採用第 2 種。更正是**指示**，不是素材。

送出的更正累積在 session 的 `corrections` list，透過 `corrections_block()` 注入三處 prompt：
`lecture_note_prompt`、`rollup_prompt`、`final_prompt`。清單為空時完全不出現，既有 prompt
一個字都不變。

更正一併寫進 `finalize_input.json`，所以「重新整併」重跑時仍然生效。

與之並行的另一條通道是**手寫筆記**（`user_notes`）：那是素材，作為最高優先的內容交給
模型整合，並額外由 `append_user_notes_section()` 在後端原文附加到 `final_notes.md` 末尾。
原文那一段刻意不請模型照抄 —— 程式拼接才能保證一字不漏。

## Consequences

好處：

- 不必為 note block 建立身分，不必管「某一段正在重跑」的狀態。
- 一次更正對之後**所有**生成有效，不用逐段修。
- 不增加 API 呼叫次數；更正只是 prompt 裡多幾行。
- 更正在最終整併時才真正發揮作用，而最終筆記正是使用者要複習的東西。

代價：

- **已經顯示在畫面上的錯誤不會當場消失。** 使用者按下更正後，看到的仍是那段錯的筆記，
  要到下課整併後才修好。`live_notes.md` 會永久保留錯的原文與下方的更正。
- 更正是否被遵守取決於模型。沒有機制能驗證輸出真的照做了。
- 更正清單會隨課堂長度單調成長，每一次生成都要付它的 input token。一堂課累積數十條更正時
  成本不可忽略，且會稀釋 prompt 中其他指示的注意力。
- 更正沒有作用範圍。寫「這裡指的是 X」時，模型不知道「這裡」是哪裡。
